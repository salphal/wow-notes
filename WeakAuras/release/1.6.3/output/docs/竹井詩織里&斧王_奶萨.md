## 3. 单位宏构建

- 单位池：`player` + `focus` + `party1-4` + `raid1-25/40`
- 每个技能 × 每个单位生成一个宏：`/cast [@单位,help,nodead] 技能`
- 迅捷链宏：`/cast 自然迅捷\n/cast [@单位,help,nodead] 治疗链`
- Action ID = 8790000 + 序号
- NOOP = 8790000 + 200000（/stopmacro 空闲动作）

## 4. 辅助函数

| 函数 | 说明 |
|------|------|
| `hasBuff/hasDebuff` | 单位 buff/debuff 检测（可限定自己施加） |
| `spellReady` | 技能就绪（CD≤1.5s 视为 GCD 过滤） |
| `inRange` | 单位在 40 码内 |
| `unitHasTOCDebuff` | 是否在特殊 debuff 名单（TOC/ICC） |
| `calcUnitHealthDiff` | 真实血量缺口 = 最大血量 - 当前血量 - 治疗预读补偿（治疗链 9000 / 激流 2500） |

**治疗预读补偿机制**：通过 trigger 追踪最近施放的治疗链/激流目标，在计算其血量缺口时扣除预计治疗量，防止对同一目标重复施法。

## 5. 核心输出逻辑 runRaid（治疗决策树）

### 数据收集（单次 O(N) 遍历）
遍历单位池，计算每个单位的调整后血量百分比，提取：
- `lowestSwiftHpPercent`（最低血单位→迅捷链候选）
- `lowestRiptideDebuffUnit`（有TOC debuff 的最低血）
- `lowestRiptideTankMoveUnit`（坦克 或 移动中最低血）
- `lowestRiptidePartyUnit`（小队最低血）
- `lowestCHUnit`（治疗链候选）
- `playerESActive`（场上是否有自己的大地之盾）、`inRangeFocusUnit`（焦点在范围）、`potentialESTank`（坦克候选）

### 优先级树（从高到低）
| 优先级 | 条件 | 动作 |
|--------|------|------|
| L20 | 自然迅捷可用 && 最低血<35% | **迅捷治疗链**（应急） |
| L19-18 | 场上无大地之盾 | 给焦点上大地之盾（无焦点→坦克） |
| L17 | 激流可用 && TOC debuff 单位血<80% | 激流（保 debuff 目标） |
| L16 | 激流可用 && (坦克 或 移动中) 血<80% | 激流 |
| L15 | 激流可用 && 小队模式 && 血<80% | 激流（小队补漏） |
| L14 | 治疗链候选血<95% && 未移动 | **治疗链**（大团地鼠填充） |
| 兜底 | 无目标 | NOOP（/stopmacro） |

## 6. 性能优化

`APLCallback` 每 0.5 秒才重新计算一次（`now-lastTime >= 0.5`），且 GCD 就绪时才执行，缓存上次动作 ID。**代价**：非 GCD 技能可能延后。
